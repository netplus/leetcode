# 单调栈：从暴力搜索到“未决问题一次结算”

> 这篇文档既是单调栈学习笔记，也是本仓库后续单调栈题的专项讲解规范。目标不是背“递增栈 / 递减栈模板”，而是能够从题意重新推导出栈中保存什么、什么时候弹栈、边界公式为什么成立，以及重复元素应该如何归属。

## 1. 先认识这类题在重复做什么

单调栈常见于三类问题：

1. **Next Greater / Smaller**：左边或右边第一个更大 / 更小元素；
2. **边界扩展**：某个元素作为限制值时，最多能向左右延伸到哪里；
3. **贡献统计**：某个元素作为子数组最小值 / 最大值时，能负责多少个子数组。

不要先问“这题用递增栈还是递减栈”。先写出一个自然的朴素算法，并问：

```text
我是不是在为很多位置反复向左 / 向右寻找第一个满足条件的元素？
```

若答案是肯定的，再继续问：

```text
从左到右扫描时，哪些历史位置的答案还没有确定？
当前元素到来后，哪些历史问题第一次可以确定答案？
```

单调栈通常就是把这些“尚未解决的问题”保存起来。

---

## 2. 单调栈真正维护的不是“有序”，而是未决候选

以 LC-739「每日温度」为例。暴力做法是：对每一天向右寻找第一个更暖的日期，最坏 O(n^2)。

换成从左到右扫描后，栈中保存：

> **已经出现、但还没有找到右侧第一个更暖日期的下标。**

当前温度比栈顶温度高时：

```text
当前 day
   ↓
... 75 71 69 | 72
        ↑  ↑
      未决 未决

72 > 69 -> 69 的答案第一次确定，pop
72 > 71 -> 71 的答案第一次确定，pop
72 < 75 -> 75 继续等待
```

因此代码里的 `pop` 不是为了机械地“维持单调性”，而是因为：

> **栈顶这个历史问题已经被当前元素结算，继续留栈没有意义。**

单调性只是所有仍然未决的候选经过不断结算以后自然形成的形状。

### 一个更可靠的推导顺序

遇到单调栈题时，按下面顺序想：

```text
1. 栈中保存什么“尚未确定”的问题？
2. 当前元素在什么条件下可以解决 / 淘汰栈顶？
3. pop 时能够确定什么答案？
4. pop 完以后，新的 stack.top() 又代表什么？
5. 当前元素最后为什么还要入栈？
```

最后才给它贴上“单调递增 / 单调递减”的名字。

## 3. 第一层：Next Greater / Smaller

### 3.1 右边第一个更大

当前值比栈顶大时，栈顶的答案确定：

```cpp
vector<int> nextGreater(n, -1);
stack<int> pending;  // 存下标

for (int i = 0; i < n; ++i) {
    while (!pending.empty() && a[i] > a[pending.top()]) {
        int j = pending.top();
        pending.pop();
        nextGreater[j] = i;
    }
    pending.push(i);
}
```

此时留下来的值自然是从栈底到栈顶单调不增。

### 3.2 为什么当前元素一定是“第一个”

如果下标 `j` 一直留到当前 `i` 才被弹，说明在 `(j, i)` 之间从未出现过能够解决 `j` 的元素；否则 `j` 早就已经在更早时刻被弹出。

所以按扫描顺序第一次触发 pop 的元素天然就是“右侧第一个”满足条件的元素。

### 3.3 为什么默认存下标

下标同时保留：

```text
a[index]   -> 值
index      -> 位置
current-index -> 距离
```

LC-739 需要计算等待天数，因此只存温度是不够的。除非题目只关心数值，否则单调栈默认存 index。

## 4. 第二层：边界扩展——LC-84 的核心模型

LC-84 难点不应该从 `while (heights[top] > current)` 开始，而应该从矩形本身开始。

### 4.1 原始数学模型

对任意连续区间 `[L, R]`：

```text
宽度 = R-L+1
高度 = min(heights[L..R])
```

因此：

```text
area(L,R) = (R-L+1) * min(heights[L..R])
```

最自然的暴力方法就是枚举区间；即使扩展区间时顺便维护最小值，仍有 O(n^2) 个候选区间。

### 4.2 第一次关键变形：不要枚举区间，枚举“限制高度”

任何合法矩形的高度一定等于区间中的某根最低柱。

于是把问题改写成：

> **固定 `heights[i]` 作为矩形最低高度，它最多能够向左右延伸到哪里？**

例如：

```text
index:   0  1 | 2  3 | 4  5
height: [2, 1 | 5, 6 | 2, 3]
             ^ h=5
```

固定高度 `5`：

- index 3 的高度 6 >= 5，可以包含；
- index 1 的高度 1 < 5，左边被挡住；
- index 4 的高度 2 < 5，右边被挡住。

因此概念上的两个阻挡边界是：

```text
left  = 1
right = 4
```

真正可用的柱子在开区间 `(left, right)` 中，即闭区间：

```text
[left+1, right-1] = [2, 3]
```

### 4.3 `width = right-left-1` 不应该背

由闭区间长度公式：

```text
length = end-start+1
```

代入：

```text
start = left+1
end   = right-1
```

得到：

```text
width
= (right-1) - (left+1) + 1
= right-left-1
```

所以这里的 `-1` 不是模板技巧，而是因为：

> **左右阻挡柱本身都比目标高度矮，不能进入矩形。**

### 4.4 先写出正确的 O(n^2) 基线

在学习单调栈前，应该先能写出：

```cpp
for (int i = 0; i < n; ++i) {
    int left = i;
    int right = i;

    while (left - 1 >= 0 && heights[left - 1] >= heights[i])
        --left;

    while (right + 1 < n && heights[right + 1] >= heights[i])
        ++right;

    int width = right - left + 1;
    answer = max(answer, heights[i] * width);
}
```

这个算法已经把题意建模正确了。它慢在：

> **不同柱子会反复扫描同一批位置，只为了寻找最近的更矮边界。**

这才是单调栈要优化掉的工作。

## 5. LC-84 为什么一次 pop 能结算矩形

维护高度单调不降的下标栈，并从左向右扫描。

栈的语义是：

> **这些柱子还没有遇到一个能够让它们向右扩展终止的更矮高度。**

例如：

```text
heights = [2,1,5,6,2,3]

扫描到 index=4, current=2 前：
stack 对应高度可能为 [1,5,6]

current=2 到来：
2 < 6 -> 6 的右侧阻挡位置确定，pop 6
2 < 5 -> 5 的右侧阻挡位置确定，pop 5
1 < 2 -> 停止
```

对于被弹出的高度 `h`：

```text
rightBoundary = 当前 i
leftBoundary  = pop 后的新 stack.top()，栈空则视作 -1
width         = i-leftBoundary-1
```

这里有两个不同层次必须区分：

1. **数学模型**：固定一个高度时，希望找到两侧最近的严格更矮阻挡；
2. **具体实现**：比较符号决定相等高度如何保留、由谁代表更宽区间。

不要把这两层混成一句“pop 后栈顶永远是严格更矮”。

---

## 6. 重复元素：比较符号不是细节，而是归属规则

这是单调栈最容易写错、也最容易讲错的地方。

LC-84 当前实现使用：

```cpp
while (!st.empty() && heights[st.top()] > currentHeight)
```

也就是只在**严格下降**时弹栈，因此相等高度可以同时留在栈中。

例如两个等高柱 `5,5`：后一根 5 被结算时，左侧栈顶可能仍然是前一根 5，而不是严格更矮柱。于是后一根得到的区间可能较窄；但前一根 5 后续被弹时会得到更宽区间，因此全局最大面积仍不会遗漏。

所以讲解必须明确：

> **严格 / 非严格比较决定相等元素由谁负责某段区间。**

在“所有子数组最小值之和”一类贡献题里，这一点更加关键。左右两侧通常要采用不对称的严格性，例如：

```text
左边找 <
右边找 <=
```

或者反过来，目的是让相等元素对同一个子数组只有一个负责人，避免重复统计。

## 7. 第三层：从边界扩展到贡献统计

如果题目问：

```text
所有子数组的最小值 / 最大值之和
```

不要枚举所有子数组，可以换成：

> **枚举每个元素作为最小值 / 最大值时，它能负责多少个子数组。**

设某元素左侧可选择 `L` 个起点，右侧可选择 `R` 个终点，则：

```text
负责的子数组数量 = L * R
贡献 = value * L * R
```

于是问题再次转成“左右边界在哪里”，再由单调栈求边界。

学习递进关系可以记成：

```text
LC-739：pop -> 确定一个右侧答案
    ↓
LC-84：pop -> 右边界；pop 后 top -> 左侧阻挡；由边界算宽度
    ↓
LC-907 / LC-2104 类：由左右边界距离 -> 计算每个元素的子数组贡献
```

仓库当前未收录 LC-907 / LC-2104 时，不需要为了凑模板创建题目；以后加入这类题时，应沿用本节的边界与重复元素归属规则。

## 8. 统一代码骨架：pop / query / push

比背“递增栈 / 递减栈”更稳定的模板是：

```cpp
for (int i = 0; i < n; ++i) {
    while (!st.empty() && current_can_resolve_or_eliminate_top(i, st.top())) {
        int j = st.top();
        st.pop();

        // pop 时结算 j 的右侧答案 / 区间 / 贡献
    }

    // 某些题在这里读取 pop 后的新 st.top()，得到左侧最近合法候选

    st.push(i);  // 当前元素成为新的未决候选
}
```

思维顺序：

```text
pop   = 哪些历史问题现在第一次可以结算？
query = 清掉无效候选后，最近仍合法的历史候选是谁？
push  = 当前元素还缺什么未来信息，因此为什么需要留下？
```

## 9. 哨兵在单调栈中的作用

LC-84 扫描结束时，可能还有递增尾巴没有遇到右侧更矮柱。

与其循环结束后再写一套清栈逻辑，不如在 `i=n` 时虚拟一个高度 0：

```text
真实柱子 ... | virtual 0
```

它会触发正常的“更矮事件”，让所有残留历史状态按同一逻辑结算。

左边没有真实阻挡时，同理可使用虚拟下标：

```text
leftBoundary = -1
```

于是公式仍然统一：

```text
width = right-left-1
```

哨兵的本质不是特殊值本身，而是：

> **人为制造一个必然发生的正常事件，让边界情况复用主流程。**

详见 [哨兵 / 虚拟边界](tricks/sentinel.md)。

## 10. 为什么总复杂度是 O(n)

虽然代码通常是 `for + while`：

```cpp
for (...) {
    while (...) st.pop();
}
```

但每个下标：

```text
最多 push 一次
最多 pop 一次
```

所有循环合计最多 O(n) 次入栈和 O(n) 次出栈，所以总时间是摊还 O(n)，空间 O(n)。

判断复杂度时要统计一个元素在整个生命周期被处理多少次，而不是只看语法上是否有嵌套循环。

## 11. 本仓库单调栈题的专项讲解规范

后续新增或修改单调栈题，除 `AGENTS.md` 的通用教学规则外，至少检查以下内容：

1. **从题意建模开始**：先说明原问题真正枚举 / 查询的是什么，不直接从栈模板开始；
2. **给真实朴素解**：当优化跨度明显时，给一个自然且正确的 O(n^2) 或等价基线；
3. **点名重复工作**：明确优化掉的是“反复寻找最近更大 / 更小边界”还是“保存了已被支配候选”；
4. **定义栈语义**：写清“栈中每个元素为什么还没有被弹，它还在等什么”；
5. **定义 pop 事件**：当前元素为什么能够在这一刻第一次结算栈顶；
6. **边界公式必须推导**：例如 `right-left-1` 要从 `(left,right)` / `[left+1,right-1]` 推出，不作为魔法常数记忆；
7. **严格性必须说明**：`< / <= / > / >=` 对重复元素的归属有什么影响；
8. **默认解释为什么存 index**：尤其当答案涉及距离、宽度或位置；
9. **哨兵必须解释语义**：它代表哪个虚拟边界 / 哪个强制结算事件；
10. **给摊还复杂度理由**：每个元素最多入栈一次、出栈一次；
11. **至少手推一次 multi-pop**：让读者看见一个新元素如何批量结算多个历史元素；
12. **说明迁移层级**：Next Greater/Smaller -> 左右边界 -> 贡献统计，而不是只列相似题号。

如果讲解无法回答下面四个问题，就还不够可复现：

```text
栈里到底存的是什么？
为什么现在可以 pop？
pop 时到底确定了什么？
比较符号换成 >= / <= 后，重复元素的归属会发生什么？
```

## 12. 复习卡片

看到“最近更大 / 更小、直到遇到某边界、每个元素作为 min/max 的作用范围”时：

```text
先写朴素搜索
    ↓
找出重复的左右边界扫描
    ↓
定义未决问题
    ↓
问 current 何时能结算 top
    ↓
pop / query / push
    ↓
最后再确认递增还是递减、严格还是非严格
```

最值得记的一句话是：

> **单调栈不是为了维护单调而存在；它是在扫描过程中只保留仍未解决、仍有资格影响未来的历史候选，并在触发事件到来时一次结算。**
