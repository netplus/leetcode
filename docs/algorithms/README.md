# 专项算法文档 / Algorithm Guides

这里收录“把一类具体问题抽象成统一机制”的专项算法文档。

`docs/patterns.md` 只承担速查：看到什么特征、常见代码骨架是什么；本目录负责解释 **为什么会有这类算法、它从什么一般性问题推导出来、适用边界在哪里、不同变体为什么成立**。

## 为什么需要专题文档

一道题的题解只应重点回答“这个具体问题如何映射到某个通用机制”。如果每道题都从零重新解释单调栈、双指针、滑动窗口等完整理论，会造成重复；如果只写一句“这里使用单调栈”，又会让算法变成需要死记的黑盒。

因此仓库采用两层结构：

```text
具体题目
  先讲题目自身的直觉、一般解法、限制和规律
          ↓
  识别出某个可复用算法机制
          ↓
专项算法文档
  解释该机制的一般模型、推导、变体、边界和复杂度
          ↓
回到具体题目
  说明这道题如何实例化该机制，并落到代码
```

## 专项算法文档的统一结构

一个非平凡的专项算法文档，原则上按以下顺序组织：

1. **它解决哪一类一般问题**：不用算法名先描述问题形状；
2. **最自然的一般实现**：给出人能直接想到的正确方法；
3. **一般实现的限制**：指出重复搜索、重复计算、被支配候选、状态无法复用等瓶颈；
4. **抽象出一般规律**：说明哪些信息真正需要保留、什么事件能一次排除或结算一批状态；
5. **图形化推导**：只要关系具有空间、区间、边界、移动、层次结构，就优先用 ASCII / Mermaid / 几何示意图展示；
6. **必要背景知识**：只在首次需要时定义，例如开闭区间、严格/非严格关系、LIFO、摊还分析；
7. **正式引入算法**：这时才给出算法名、核心数据结构和标准不变量；
8. **常见变体**：比较符号、扫描方向、边界策略、状态定义改变时分别意味着什么；
9. **正确性与复杂度**：解释为什么不会漏、不会重、为什么复杂度成立；
10. **题目递进路径**：从基础题到边界题、贡献题或更复杂组合，说明“多了哪一层抽象”。

算法专题不是模板收藏。读完后应能够在忘记模板的情况下，从问题重新推导出核心机制。

## 后续专题

当仓库再次系统整理以下算法族时，应按同一规范建立专题文档，而不是只在 `patterns.md` 增加模板：

- 双指针；
- 滑动窗口；
- 前缀和 / 差分；
- 二分搜索 / 答案二分；
- 单调队列；
- 动态规划的状态设计与压缩；
- BFS / DFS 的 frontier 与状态语义；
- 并查集；
- 回溯与剪枝。

不要求为了目录完整而一次性创建空文档；当某类算法开始承担多道题的共同解释时，再建立并持续维护对应专题。
