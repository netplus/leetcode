# 专项算法文档 / Algorithm Guides

这里收录“把一类具体问题抽象成统一机制”的专项算法文档。

`docs/patterns.md` 只承担理解后的速查；本目录负责解释 **为什么会有这类算法、它从什么一般问题推导出来、适用边界在哪里、不同变体为什么成立**。

## 仓库统一学习路径

```text
具体题目直觉 / 图形模型
        ↓
最自然的一般实现
        ↓
一般实现的限制 / 重复工作
        ↓
抽象可复用规律
        ↓
第一次需要时补充背景知识
        ↓
映射到专项算法
        ↓
专题文档解释通用机制
        ↓
回到具体题目落到公式、不变量与代码
```

算法名是检索标签，不是推理前提。

## 专项文档统一结构

一个非平凡专题至少回答：

1. 它解决哪类一般问题；
2. 最自然的一般实现是什么；
3. 一般实现重复做了什么 / 保存了哪些无用状态；
4. 哪个规律允许复用、淘汰或压缩状态；
5. 能否用区间图、指针图、状态图、树图等把关系画出来；
6. 首次需要的背景概念是什么；
7. 正式算法的数据结构 / 状态语义；
8. 常见变体与严格/非严格边界；
9. 正确性与复杂度；
10. 从基础题到进阶题的迁移路径。

## 当前专题

### 数组 / 字符串 / 扫描

- [哈希索引](hash-indexing.md) — 把重复线性搜索变成 key -> state 查询。
- [前缀和与差分](prefix-sum-difference.md) — 累计状态、区间查询、边界事件。
- [双指针](two-pointers.md) — 证明一个边界可以永久移动，批量淘汰候选。
- [滑动窗口](sliding-window.md) — 复用高度重叠区间的增量状态。
- [KMP](kmp.md) — 失配时复用已经匹配成功的前后缀。
- [区间排序与扫描线](interval-sort-sweep.md) — 先制造顺序，再维护当前活动区间。

### 栈 / 队列 / 候选压缩

- [栈与队列](stack-queue.md) — 未完成上下文、LIFO 与 BFS frontier。
- [单调栈](monotonic-stack.md) — 未决历史状态由未来边界事件一次结算。
- [单调队列](monotonic-queue.md) — 在移动窗口中删除被新候选永久支配的旧候选。

### 链表 / 树 / 搜索

- [链表指针技巧](linked-list-pointer.md) — 局部重连、dummy、快慢指针、反转与归并。
- [树遍历与树形状态](tree-traversal.md) — 先定义子树返回值，再决定前/中/后序或 BFS。
- [回溯](backtracking.md) — 当前路径、可选集合、撤销与剪枝。
- [图搜索与拓扑排序](graph-search-toposort.md) — frontier、连通分量、多源 BFS、依赖消除。
- [并查集](union-find.md) — 只维护动态连通集合的代表元。

### 优化 / 选择

- [动态规划](dynamic-programming.md) — 从重复子问题推导状态、转移与状态压缩。
- [二分搜索](binary-search.md) — 在单调候选空间 / 答案空间中一次排除一半。
- [贪心](greedy.md) — 用支配或交换论证证明当前选择不会损失全局最优。
- [堆与 Top-K](heap-topk.md) — 只维护当前最有竞争力的一小批候选。

## 维护规则

当一道题明确依赖上述算法族时，题解的“专项算法背景”应指向对应专题，并只解释“这道题怎样实例化这个通用机制”，避免每题重新复制整篇理论。

如果出现新的算法族并开始承担多道题的共同解释，应先建立专题，再让具体题目引用；不要只往 `docs/patterns.md` 添加一段代码模板。
