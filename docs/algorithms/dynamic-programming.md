# 动态规划：把重复子问题压缩成状态

## 1. 先不要找“dp 公式”

DP 的起点是：暴力搜索中，是否有不同路径反复到达同一个剩余问题？如果未来只由一个小状态决定，就没必要保留完整历史路径。

## 2. 状态定义

先用一句话定义 `dp[...]` 到底表示什么。例如：

```text
dp[i]    = 前 i 间房能抢到的最大金额
dp[r][c] = 到达格子 (r,c) 的最小代价
dp[i][j] = 两个前缀的 LCS 长度
```

没有状态语义就直接写转移式，公式会变成记忆负担。

## 3. 转移 = 枚举最后一步

常见问题是“当前状态最后一步可能从哪里来？”：爬楼梯来自 i-1/i-2，网格来自上/左，LCS 取决于两个末字符，背包来自选/不选当前物品。

## 4. 初始化

初始化应回到状态定义：`dp[0]` 为什么是这个值，而不是背模板。

## 5. 状态压缩

如果第 i 行只依赖上一行，可以滚动数组。一维背包中更新方向有语义：0/1 背包倒序表示当前物品这一轮最多用一次；完全背包正序表示当前物品可继续影响更大容量。

## 6. 区间 DP

当操作会动态改变邻居关系时，常尝试改变决策顺序，例如枚举“最后一个操作”，让区间外边界在子问题中固定下来。

## 7. 候选支配

DP 还能继续优化。LIS 的 tails 就是在同长度候选里只保留最小尾值，因为面对同一个未来，它永远不劣于更大尾值。

## 8. 复杂度

状态数 × 每个状态枚举的转移数。先数状态，再数每个状态做多少工作，比盯着循环层数更可靠。
