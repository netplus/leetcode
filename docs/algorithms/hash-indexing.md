# 哈希索引：把重复搜索变成直接查询

## 1. 它解决哪类一般问题

很多题的自然写法都是：当前拿到一个值或状态，然后在历史里寻找某个已经确定的目标 key。如果每次都从头扫描历史，就会重复做同一种查找。

以 Two Sum 为例：当前 `x` 一旦确定，另一个数只能是 `target-x`。真正慢的不是计算补数，而是反复寻找补数是否出现过。

## 2. 最自然的一般实现

```text
for 当前元素:
    在历史中逐个寻找 targetKey
```

这个实现通常完全正确，但第 i 次查询可能检查 O(i) 个历史元素，总成本容易达到 O(n^2)。

## 3. 抽象规律

如果查询 key 能由当前状态直接算出，而且历史只增不减，就可以建立：

```text
key -> 需要保存的信息
```

把“重新搜索”改成一次直接查询。

信息可以是：存在性、出现次数、最近下标、任意下标、对象身份映射等。

## 4. 正式引入哈希

常用结构：

```cpp
unordered_set<Key>
unordered_map<Key, Value>
```

`set` 只回答 key 是否存在；`map` 还保存与 key 关联的状态。

## 5. 查询与更新顺序

Two Sum 一类问题通常要先查历史、再记录当前：

```text
查 target-x
    ↓
若找到，它一定来自旧位置
    ↓
再把当前 x 写入历史
```

这个顺序来自题意，而不是模板记忆。

## 6. 频次与存在性

计数题不能把频次退化成存在性。一个历史 key 出现 3 次，往往代表 3 个不同候选，贡献也应计 3 次。

## 7. 原地哈希

若值域与数组下标天然一一对应，例如 `x∈[1,n]` 映射到槽位 `x-1`，输入数组本身就可以承担索引表角色，进一步省掉辅助哈希空间。

## 8. 典型题

- LC-1：补数 -> 历史下标
- LC-128：值是否存在 + 唯一链头
- LC-41：值域映射到数组槽位
- LC-133：原图节点 -> 克隆节点
- LC-3：字符 -> 最近位置
