# 哨兵 / 虚拟边界（Sentinel）

哨兵不是某一道题的固定模板，也不是“看到边界就填一个 `-1`”。

它更像一种很通用的**边界归一化技巧**：

> 当算法主体已经有一套很漂亮的统一规则，但“第一次、最左边、空结构、尚未找到答案”等边界情况无法直接套进去时，主动补一个虚拟状态，让边界也满足同一套规则。

换句话说，哨兵真正解决的是这类问题：

```text
主体逻辑很统一
    ↓
但是边界不符合主体逻辑
    ↓
不得不额外写 if / else
```

如果我们能给边界补出一个“合理的前置状态”，就可能变成：

```text
真实状态 + 一个虚拟状态
        ↓
全部满足同一个公式 / 同一个指针操作
        ↓
边界分支消失
```

这就是 sentinel 最值得记住的思想。

---

## 1. 这到底是一类什么技巧？

刷题时，大量 bug 并不出现在算法主体，而出现在边界：

- 第一个元素怎么处理？
- 区间刚好从下标 `0` 开始怎么办？
- 字符从没出现过怎么办？
- 链表还是空的，第一次插入怎么办？
- 一直没找到答案，最后怎么判断？
- DP 访问到“空区间”怎么办？

这些情况有一个共同点：

> **主流程已经知道怎么处理“普通状态”，只是缺少一个能代表边界的状态。**

哨兵的做法不是继续增加特殊判断，而是**扩展状态空间**。

例如数组真实下标是：

```text
0  1  2  3  ...
```

为了统一公式，我们可以在脑中补一个：

```text
-1 | 0  1  2  3 ...
 ^
虚拟位置
```

或者在链表真正头节点前补一个：

```text
[dummy] -> [node1] -> [node2] -> ...
   ^
虚拟头节点
```

这个虚拟东西不一定属于题目的真实数据，但它能让算法的主规则从边界开始就成立。

所以可以把哨兵记成一句话：

> **不是特殊处理边界，而是把边界改造成普通情况。**

---

## 2. 什么场景最值得想到哨兵？

新手不需要见到所有边界都尝试 sentinel。最值得警觉的是下面几种信号。

### 场景一：代码里出现“第一次 / 从未出现”分支

例如：

```cpp
if (这个字符以前没出现过) {
    ...
} else {
    按正常公式处理
}
```

这通常意味着：

> “从未出现”是不是也可以被描述成“上一次出现在某个虚拟位置”？

LC-3 的 `last[c] = -1` 就属于这一类。

---

### 场景二：从数组开头开始的区间总要特判

例如前缀和：

```cpp
if (left == 0) {
    sum = prefix[right];
} else {
    sum = prefix[right] - prefix[left - 1];
}
```

这说明当前前缀定义没有把“数组开始之前”建模进去。

更自然的方式是人为补一个空前缀：

```text
数组开始之前：累计和 = 0
```

于是所有区间都变成统一的“右边界累计 - 左边界累计”。

LC-560、LC-303、LC-304 都能看到这个思想。

---

### 场景三：链表头节点总是特殊

例如往结果链表接第一个节点时：

```cpp
if (head == nullptr) {
    head = node;
    tail = node;
} else {
    tail->next = node;
    tail = node;
}
```

第一次插入和后面的插入走了两条逻辑。

这时常见做法是补一个 dummy 头：

```text
[dummy] -> 真正的数据节点...
```

于是第一次插入也只是：

```cpp
tail->next = node;
tail = node;
```

LC-21 是最典型的例子。

---

### 场景四：需要表示“还没有答案”

例如求最小值：

```cpp
bool found = false;
int best;

if (找到候选答案) {
    if (!found) {
        best = candidate;
        found = true;
    } else {
        best = min(best, candidate);
    }
}
```

如果我们知道所有真实答案都满足：

```text
answer <= n
```

那么可以直接令：

```cpp
int best = n + 1;
```

之后每个候选都统一：

```cpp
best = min(best, candidate);
```

最后：

```cpp
return best == n + 1 ? 0 : best;
```

LC-209 就是这种“**不可能值哨兵**”。

---

## 3. 哨兵背后的核心规律：让“不存在”也拥有一个状态

这是整篇最重要的一层。

很多算法公式其实隐含着一个前提：

```text
前一个状态必须存在
```

但边界恰恰没有“前一个真实状态”。

于是朴素写法只能说：

```text
如果前一个状态存在 -> 按公式处理
否则               -> 特判
```

哨兵则换了一种建模方式：

```text
真实世界里不存在
        ↓
算法模型里给它补一个虚拟状态
        ↓
让主公式继续成立
```

因此，设计一个哨兵时真正要问的不是：

> “这里应该填 `-1` 还是 `0`？”

而是：

> **“如果这个边界之前真的存在一个虚拟状态，它应该是什么，才能让我的主公式仍然成立？”**

下面用几道已经很熟悉的题看这个规律。

---

# 4. LC-560：空前缀为什么是 `frequency[0] = 1`

这是理解 sentinel 最好的例子之一。

题目统计“和为 `k` 的连续子数组”。

我们已经知道前缀和的图像：

```text
数组：        [ ............ 连续区间 ............ ]

过去累计  ------------------|
当前累计  ----------------------------------------|

          当前累计 - 过去累计
                  =
              中间区间和
```

公式就是：

```text
prefix - oldPrefix = k

所以：
oldPrefix = prefix - k
```

扫描到当前 `prefix` 时，只需要问：

> 历史上有多少次累计到了 `prefix-k`？

## 4.1 普通情况

例如：

```text
nums = [1, 2, 3]
k = 3
```

扫描到最后一个 `3`：

```text
当前 prefix = 6
需要 oldPrefix = 6 - 3 = 3
```

历史上确实曾经累计到 `3`：

```text
[1, 2] | [3]
   3       3
```

相减以后中间 `[3]` 的和就是 `3`。

没有任何特殊情况。

---

## 4.2 真正的边界：答案从下标 0 开始

还是：

```text
nums = [1, 2, 3]
k = 6
```

扫描到最后：

```text
prefix = 6
oldPrefix = prefix - k = 0
```

我们需要找到一个历史前缀 `0`。

可是数组里什么位置的前缀和是 `0`？

关键就在这里：

```text
数组开始之前，一个元素都还没看：
累计和当然是 0。
```

把数组边界画出来：

```text
       空前缀
          ↓
      |  1  |  2  |  3  |
      ^                 ^
      0                 6
```

所以 `frequency[0] = 1` 的真正语义不是：

> “这是前缀和模板规定的初始化。”

而是：

> **在扫描开始前，已经存在一次“累计和为 0”的虚拟历史。**

代码：

```cpp
unordered_map<long long, int> frequency;
frequency[0] = 1;  // 空前缀出现一次

long long prefix = 0;
int answer = 0;

for (int value : nums) {
    prefix += value;

    auto it = frequency.find(prefix - k);
    if (it != frequency.end()) {
        answer += it->second;
    }

    ++frequency[prefix];
}
```

于是：

```text
中途开始的区间
和
从下标 0 开始的区间
```

完全走同一个公式。

这就是一个标准的 sentinel。

### 这里的规律

`0` 并不是因为“哨兵喜欢用 0”。

而是因为：

```text
空前缀的累计和 = 0
```

它必须由状态语义推出来。

---

# 5. LC-1248：为什么可以原样继承 LC-560 的哨兵

LC-1248 要求“恰好有 `k` 个奇数”。

先做转换：

```text
奇数 -> 1
偶数 -> 0
```

例如：

```text
原数组： [2, 2, 1, 2, 1, 2]
映射后： [0, 0, 1, 0, 1, 0]
```

问题立即变成：

> 有多少个连续子数组的和等于 `k`？

也就是 LC-560。

这时 `prefix` 的含义从：

```text
累计元素和
```

变成：

```text
累计奇数个数
```

但是扫描开始前：

```text
一个元素都没看
=> 遇到的奇数个数 = 0
```

所以虚拟状态仍然是：

```cpp
frequency[0] = 1;
```

这说明一个很重要的迁移规律：

> **哨兵依附的是“状态语义”，不是题号。只要状态模型没变，哨兵往往也能一起复用。**

---

# 6. LC-3：把“从未出现”建模成“出现在 -1”

再看另一种完全不同的题型。

LC-3 维护一个无重复滑动窗口：

```text
        left                 right
          ↓                     ↓
... [ 当前没有重复字符的窗口 ] [c]
```

如果当前字符 `c` 上一次出现在位置 `j`，为了排除旧的 `c`，左边界至少要移动到：

```text
j + 1
```

因此统一公式是：

```cpp
left = max(left, last[c] + 1);
```

问题来了：

> 如果 `c` 从来没出现过，`last[c]` 是多少？

朴素思路会写：

```cpp
if (c 从未出现) {
    left 不动;
} else {
    left = max(left, last[c] + 1);
}
```

但换一个角度：

如果我们把“从未出现过”理解成：

```text
它上一次出现在数组开始之前的位置 -1
```

那么：

```text
last[c] = -1
last[c] + 1 = 0
```

而 `left >= 0`，所以：

```text
max(left, 0) = left
```

恰好表示“left 不动”。

于是初始化：

```cpp
array<int, 256> last;
last.fill(-1);
```

整个扫描过程中都可以无条件执行：

```cpp
left = max(left, last[c] + 1);
```

### 图像上怎么理解

真实字符串的位置：

```text
 0   1   2   3 ...
```

人为补一个虚拟位置：

```text
-1 | 0   1   2   3 ...
 ^
“还没出现过”
```

所以 `-1` 也不是魔法值。

它来自公式：

```text
last[c] + 1
```

我们希望“从未出现”时结果正好变成合法起点 `0`：

```text
sentinel + 1 = 0
sentinel = -1
```

这就是**从公式反推哨兵值**。

# 7. 链表 dummy：哨兵不一定是一个数字

很多初学者会把 sentinel 理解成 `-1`、`0`、`INF` 这样的特殊数字。

其实它也可以是一个真实的数据结构节点。

以 LC-21 合并两个有序链表为例。

我们希望始终执行：

```cpp
tail->next = chosen;
tail = tail->next;
```

但是如果结果链表一开始是空的，就会遇到：

```text
tail 在哪里？
第一个节点谁来接？
```

朴素写法往往需要：

```cpp
if (head == nullptr) {
    head = chosen;
    tail = chosen;
} else {
    tail->next = chosen;
    tail = chosen;
}
```

注意，第一个节点其实没有算法上的特殊性。

它特殊，只因为：

```text
它前面没有真实节点。
```

那么就人为造一个：

```text
[dummy] -> [第一个真实节点] -> [第二个真实节点] -> ...
   ^
 tail 初始在这里
```

代码立即统一：

```cpp
ListNode dummy;
ListNode* tail = &dummy;

while (list1 && list2) {
    ...
    tail->next = chosen;
    tail = tail->next;
}

return dummy.next;
```

### 这里的规律

前缀和里的 sentinel 是：

```text
虚拟前缀
```

LC-3 里的 sentinel 是：

```text
虚拟位置
```

链表里的 sentinel 是：

```text
虚拟节点
```

形式不同，但本质完全一样：

> **真实结构缺少一个边界状态，于是人为补出来，让主体操作可以从第一步开始就统一。**

# 8. LC-209：另一类哨兵——“不可能成为真实答案”的值

前面的例子都在补一个虚拟状态。

还有一类常见写法是：

> 用一个真实答案绝不可能取到的值，表示“答案尚未产生”。

LC-209 要找最短合法子数组。

真实答案长度只能是：

```text
1 ~ n
```

于是可以初始化：

```cpp
int best = n + 1;
```

`n+1` 永远不可能是真实答案，因此它可以代表：

```text
目前还没找到任何合法窗口
```

之后所有候选都直接执行：

```cpp
best = min(best, right - left + 1);
```

最后：

```cpp
return best == n + 1 ? 0 : best;
```

这类哨兵和 `frequency[0]=1` 有一点区别：

- `frequency[0]=1` 是**补一个虚拟状态，使主公式成立**；
- `best=n+1` 是**用不可能值编码“尚无答案”状态**。

它们都属于 sentinel 思维，但设计依据不同。

# 9. 到这里可以抽象出两大类 sentinel

对刷题而言，先掌握下面两类已经足够覆盖大量场景。

## 9.1 类型 A：虚拟状态 / 虚拟边界

目的：

> 让边界也能直接使用算法主体的公式或指针操作。

常见形式：

| 场景 | 虚拟状态 | 作用 |
|---|---|---|
| 前缀和 | 空前缀 `prefix=0` | 从下标 0 开始的区间无需特判 |
| 最近位置 | 虚拟下标 `-1` | “从未出现”也能进入位置公式 |
| 链表 | dummy head | 第一个真实节点和后续节点统一处理 |
| 双向链表 | dummy head / tail | 头插、尾删、中间删统一指针操作 |
| DP | 第 0 行 / 第 0 列、空状态 | 边界转移直接复用递推式 |

它的核心问题是：

> **主公式缺的那个“前一个状态”应该长什么样？**

---

## 9.2 类型 B：不可能值 / 极值哨兵

目的：

> 用一个真实答案不可能等于的值，编码“尚未得到有效状态”。

常见形式：

```cpp
int best = n + 1;      // 求最短长度
long long dist = INF;  // 尚不可达
int maximum = INT_MIN; // 尚未看到真实最大值
```

但这里必须格外注意：

> `INF`、`-1`、`INT_MIN` 并不是天然就是 sentinel。

只有当它们有清晰的状态语义，并且不会和合法状态混淆时，才是安全的设计。

# 10. 如何自己推导一个哨兵，而不是背模板？

这是做题时真正可复用的方法。

## 第一步：先写出算法主体的统一规则

例如 LC-560：

```text
prefix - oldPrefix = k
```

LC-3：

```text
left = max(left, last[c] + 1)
```

链表：

```text
tail->next = node
```

先确认：

> **如果没有边界问题，我最希望所有状态都执行什么规则？**

---

## 第二步：找出迫使你写特殊 `if` 的边界

例如：

```text
LC-560：区间从 0 开始
LC-3：字符从未出现
链表：第一次插入
LC-209：还没找到答案
```

如果代码只有这里和主体不一样，就值得尝试 sentinel。

---

## 第三步：问“缺少的状态是什么”

不要先猜值。

先补语义：

```text
LC-560 缺：数组开始前的累计状态
LC-3   缺：第一次出现之前的位置
链表   缺：真正头节点之前的节点
LC-209 缺：尚未产生答案的状态
```

这一步最重要。

---

## 第四步：让主公式反推出 sentinel

LC-3：

```text
希望首次出现时：last[c] + 1 = 0

所以：
last[c] = -1
```

LC-560：

```text
一个元素都没看时累计和是多少？
0

所以：
frequency[0] = 1
```

LC-209：

```text
真实最短长度最大为 n

所以：
n+1 可以安全表示“尚未找到”
```

正确顺序应该是：

```text
状态语义
  ↓
主公式
  ↓
推导 sentinel
```

而不是：

```text
背住 -1 / 0 / INF
然后硬往题里塞
```

---

## 第五步：检查它会不会和真实状态冲突

至少检查三件事：

1. sentinel 是否可能本身就是合法数据？
2. sentinel 进入公式后是否始终产生正确结果？
3. sentinel 会不会造成溢出、越界或死循环？

例如：

```cpp
int dist = INT_MAX;
dist + weight   // 可能溢出
```

这种场景即使想用 INF，也应该选一个有安全余量的值，或者先判断可达性。

# 11. 一个更深的理解：很多哨兵其实是在选择“单位元”

这是进阶理解，但非常有用。

在数学结构里，有些操作存在一个“放进去等于没放”的值。

例如：

```text
加法：x + 0 = x
乘法：x * 1 = x
最小值：min(x, +∞) = x
最大值：max(x, -∞) = x
```

这些值叫作 identity element（单位元）或与其非常接近的边界构造。

于是很多算法初始化突然就不神秘了。

### 前缀和为什么从 0 开始？

```text
空集合的加法累计 = 0
```

所以：

```cpp
prefix[0] = 0;
```

### 求最小值为什么常初始化成 INF？

因为：

```text
min(INF, firstRealAnswer) = firstRealAnswer
```

第一份真实答案可以直接进入与后续完全相同的更新公式。

### 求最大值为什么常初始化成 -INF？

因为：

```text
max(-INF, firstRealAnswer) = firstRealAnswer
```

这就是 sentinel 背后更一般的规律：

> **寻找一个对主操作“中性”或“安全”的初始状态，让第一步和后续步骤同构。**

理解这一层后，很多 DP 初始化、累计量初始化、最值初始化都会变得更自然。

---

# 12. 再进阶：哨兵是在“扩展问题模型”

从更高一层看，sentinel 本质上是在做：

```text
原问题状态空间
+
少量人为构造的边界状态
=
一个更规则的新状态空间
```

例如：

### 前缀和

原来只有真实元素：

```text
nums[0], nums[1], ..., nums[n-1]
```

加入“数组开始前”这个边界：

```text
boundary 0, 1, 2, ..., n
```

于是：

```text
prefix[i] = 前 i 个元素的累计值
```

整个区间公式变得极其统一。

### 链表

原结构：

```text
head -> ... -> tail
```

扩展以后：

```text
dummyHead -> head -> ... -> tail -> dummyTail
```

所有真实节点都变成“有前驱、有后继”的普通内部节点。

### DP

很多二维 DP 故意多申请一行一列：

```cpp
vector<vector<int>> dp(m + 1, vector<int>(n + 1));
```

第 0 行、第 0 列通常不是输入里的真实元素，而是人为添加的空状态。

这样真正的数据从 `1` 开始，递推：

```text
dp[i] <- dp[i-1]
```

在第一行也有定义，不需要到处问“`i-1` 是否越界”。

所以，sentinel 并不是一个孤立的小技巧，它和很多优秀算法设计原则是相通的：

> **通过增加少量虚拟状态，换取更简单、更统一的不变量。**

# 13. 哪些东西不要混成“哨兵”？

理解概念边界也很重要。

## 13.1 `atMost(K) - atMost(K-1)` 本身不是 sentinel

这是一个计数恒等式：

```text
恰好 K = 至多 K - 至多 K-1
```

如果实现中规定：

```cpp
if (k < 0) return 0;
```

这只是为了让函数在边界输入上有定义。

它可以体现“边界归一化”的思想，但**差分公式本身不是哨兵技巧**。

---

## 13.2 二分搜索的 `[lo, hi)` / `[lo, hi]` 首先是区间约定

例如：

```text
hi = n
```

有时确实带有虚拟右边界的味道，但更核心的概念通常是：

```text
搜索区间如何定义
循环不变量是什么
```

学习二分时应该先把它归到“区间模型 / 不变量”，而不是看到 `n` 就称为 sentinel。

---

## 13.3 1-based 下标也不自动等于 sentinel

树状数组故意从 `1` 开始，主要是因为 `lowbit` 和父子关系在这种编号下更自然。

虽然 `0` 是不用的边界值，但教学上更应该先理解：

```text
为什么数据结构选择 1-based 编号
```

而不是泛化成“又一个哨兵”。

# 14. 面向刷题新手的识别口诀

做题时，如果代码突然出现一块只服务边界的分支，可以按下面顺序想：

```text
1. 主流程本来是什么统一公式？
2. 哪个边界让公式失效？
3. 这个边界是不是只是“缺了前一个状态”？
4. 能不能人为补一个虚拟状态？
5. 什么值 / 节点能让主公式在这个状态上仍然成立？
6. 它会不会和真实状态冲突？
```

可以再压缩成一句：

> **看到“第一次、最左边、空结构、尚未找到”时，先问能不能补一个虚拟状态，把特殊情况变成普通情况。**

# 15. 常见题型中的 sentinel 地图

| 题型 | 常见边界 | 常见 sentinel 思路 |
|---|---|---|
| 前缀和 / 前缀计数 | 区间从下标 0 开始 | 空前缀：累计状态为 0 |
| 滑动窗口 + 最近位置 | 元素从未出现 | 虚拟位置 `-1` |
| 单链表 | 第一个节点 / 删除头节点 | dummy head |
| 双向链表 / LRU | 插入头尾、删到空 | dummy head + dummy tail |
| DP | 第一行、第一列、空字符串、空区间 | 多开一层空状态 |
| 最短 / 最小值 | 尚未找到合法答案 | `INF`、`n+1` 等不可能值 |
| 最大值 | 尚未看到真实候选 | `-INF` / 足够小的不可能值 |
| 单调栈 | 栈中元素最终无人触发弹出 | 有时追加虚拟极值统一收尾，但必须确保不会污染真实答案 |

注意：表里的值只是**常见形式**，不是固定模板。

真正决定 sentinel 的永远是：

```text
你的状态定义 + 你的主公式 / 不变量
```

# 17. 最后只记住这张图

```text
没有 sentinel：

        普通情况 ------------> 主公式
       /
输入 --
       \
        边界情况 ------------> 特殊 if / else


加入 sentinel：

边界
  ↓
补成一个虚拟状态
  ↓
和普通状态进入同一个状态空间
  ↓
全部 -----------------------> 主公式
```

所以 sentinel 的真正价值，不只是少写几行 `if`。

更重要的是：

> **它让代码结构和算法不变量变得一致。**

当你发现一个边界分支只是因为“那里缺了一个前置状态”时，不妨先别急着写 `if`。

先问一句：

> **能不能把那个不存在的状态补出来？**

如果答案是可以，你通常就已经走到 sentinel 的门口了。
